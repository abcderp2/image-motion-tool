# image-motion-tool

画像を端末内で処理し、ふわふわ上下、呼吸、ゆっくり拡大、左右に傾く、振り子、円運動、ジャンプ、弾む伸縮、細かく揺れるの9種類の動きを付けられる、ブラウザ向けの静的Webツールです。GIF、APNG、アニメーションWebP、PNG、JPEG、WebPとして保存できます。

公開URL

https://abcderp2.github.io/image-motion-tool/

現在の公開版は画面下部にBuild 20と表示されます。

## 主な特徴

- 完全無料、登録不要、追加課金なし
- 画像の読み込み、加工、保存を端末内で行う
- 外部API、CDN、広告、アクセス解析なし
- GIFは軽量、標準、高画質の3段階
- 全フレームから代表色を作る適応型GIFパレット
- 白背景など、1色が大部分を占める画像でもパレットが黒く崩れにくい
- 透明GIFでは各フレーム後に前の描画を消し、移動時の残像を防ぐ
- 現在の動くプレビューをGIFへ変換せず軽量なCanvas再生として別タブで開き、生成後のGIF、APNG、アニメーションWebPも画面中央の別タブで確認できる
- 「左右に傾く」は足元、「振り子」は画像上部を支点にし、動きの意味を分ける
- 「呼吸」は足元を保ちながら縦横に伸縮し、「ゆっくり拡大」は等倍から拡大して元に戻る周期
- 「弾む伸縮」は足元寄りを支点に横に広がり、縦に縮みながら少し沈んで元に戻る周期
- 9種類の動きを一覧で確認でき、各ボタンを1回押すだけで好きな動きへ切り替えられる
- 動きの速さはプレビューと保存アニメーションの再生速度に反映
- アニメーション内の動作回数を通常設定で1回から4回まで指定可能
- GIF生成後は最後に生成した設定を使い、速度だけを変えて再生成できる
- 生成済みGIFを読み込み、フレーム画像を変えずに表示時間だけを変更できる
- 1対1、4対5、9対16、16対9の画面比率
- GIFは先頭と末尾がつながる周期で保存
- APNGはCanvasのフルカラーRGBAフレームを使い、透過、表示時間、フレーム順序、無限ループを保持
- APNGは各フレームを画面全体へ独立して上書きし、前フレームの消去処理に依存しない
- APNGはPNGシグネチャ、チャンク長、CRC、寸法、フレーム数、順序、表示時間、無限ループ、総展開画素数を生成前後に検査
- アニメーションWebPはRIFF、WEBP、VP8X、ANIM、ANMF、VP8またはVP8L、ALPHを生成前後に検査
- 静止画像は最大1440px
- 指ドラッグ、キーボード操作、左右反転
- 操作の取り消しとやり直し
- 設定の自動保存とJSON書き出し
- Service Workerによるオフライン起動
- 280px程度の狭い画面からデスクトップまで対応
- 外部パッケージ、ビルドツール、パッケージ管理なし

画像そのものはlocalStorage、設定JSON、Service Workerのキャッシュへ保存しません。画像を外すボタンを押すと、ブラウザ内の画像参照も解放します。

別タブ表示用の現在のプレビューは、GIFのフレーム生成や減色を行わず、専用ページのCanvasで現在の画像と設定を再生します。これにより、別タブを開くまでの待ち時間と端末の一時的な負荷を抑えます。表示ページは固定した同一オリジンのスクリプトとCSSだけを読み込み、画面全体を基準に中央配置します。Blobページで元ページの厳しいセキュリティ設定が引き継がれても表示が崩れないよう、中央配置用CSSはインラインではなく同一オリジンのpreview-page.cssから読み込みます。別タブ用のBlob URLにはクエリ文字列を追加せず、検査済みの画像URLと設定はHTMLエスケープしたdata属性で渡します。表示ページ用の一時URLは新しい表示を開くとき、画像を外したとき、ページを閉じたときに破棄し、外部へ送信しません。通常生成と速度変更後は、従来どおり生成したアニメーションそのものを使います。

速度変更用に読み込んだGIFも端末のメモリ上だけで扱います。元ファイルを変更せず、速度変更後の新しいGIFを作ります。読み込んだGIFのフレーム画像、色、透過、ループ情報は保持し、各フレームの表示時間だけを書き換えます。

## 基本操作

1. 画像を1枚選ぶとプレビューが動き始めます。表示された動きの種類一覧から好きなボタンを1回押し、移動量を設定します。
2. 「動きの速さ」を調整すると、画面上のプレビューと保存アニメーションの再生速度が同じ方向に変わります。GIFとAPNGの表示時間はフレーム間隔を100分の1秒単位に丸め、アニメーションWebPはミリ秒に変換するため、画面には概算値を表示します。
3. 「アニメーション内の動作回数」と保存形式を通常設定で選び、「GIFを保存」、「APNGを保存」または「アニメーションWebPを保存」を押します。
4. GIFを生成した後に速度だけを変える場合は、「速度を変えて再生成」を押します。最後に生成した設定の動き、画像位置、サイズ、色品質などを使い、現在の「動きの速さ」だけを反映して新しいGIFを作ります。
5. 既存のGIFを速度変更する場合は、「生成済みGIFを選ぶ」から読み込み、速度倍率を選んで「速度を変更して保存」を押します。0.5倍は表示時間が長くなり、2倍は短くなります。

このボタンは生成済みGIFの中身を直接編集しません。ページを再読み込みした場合や画像を選び直した場合は、対象画像を確認してから通常のGIF保存を行ってください。

速度変更後のGIFは、元のGIFと別のファイルとして保存されます。元ファイルは読み込み後も上書きされません。

## 画像の安全確認

画像を展開する前に、次の確認を行います。

- ファイル容量が15MB以下
- PNG、JPEG、WebPの実ヘッダー
- ヘッダー内の縦横サイズ
- 端末メモリに応じた合計画素数
- 画像展開後の寸法とヘッダー寸法の一致

生成済みGIFの速度変更では、GIF87aまたはGIF89aのヘッダー、論理画面と各フレームの寸法、色テーブル、データブロックの範囲、フレーム数、LZW情報を確認します。フレーム画像の展開やCanvas描画は行わず、入力ファイルの上限は15MBです。

SVG、HTML、不明な形式は読み込みません。保存画像はCanvasから新しく生成するため、元画像の位置情報や撮影情報などのメタデータを引き継ぎません。

## 出力上限

### GIF

- 長辺256px、360px、480px
- 2秒から5秒
- 8fps、10fps、12fps
- 総描画量1400万画素以下
- 軽量は216色の色立方体と40段階のグレーからなる固定パレット
- 標準は最大256色の適応型パレットを使用し、元の色味を優先
- 高画質はサンプリング数とパレット再調整回数を増やし、粒状補間を使用しない

GIF形式は1枚の画像で最大256色、透明度は完全な透明か不透明の2段階です。そのため、元画像と色や半透明の縁を完全一致させることはGIFの仕様上できません。このツールでは仕様上必要な減色以外の色ずれを抑えます。

透明背景では半透明の輪郭を保持できません。輪郭の滑らかさと見た目の色を優先する場合は、背景設定で白、黒、グリーンバック、または任意色を指定してください。色の正確さを最優先する静止画像はPNG、容量とのバランスを取る場合はWebPを使用します。

### APNG

- GIFと同じ長辺256px、360px、480px、2秒から5秒、8fps、10fps、12fpsを使用
- 総処理画素数は通常端末で1400万画素以下、端末メモリが2GB以下の場合は800万画素以下
- 推定出力は通常端末で32MB以下、端末メモリが2GB以下の場合は16MB以下
- 生成前に処理画素数、再生時間、推定メモリ、推定出力サイズを確認し、上限を超える設定を拒否
- 各フレームはCanvas標準のPNGとして生成し、CRCを確認したIDATデータだけをAPNGへ組み立てる
- 8ビットRGBAのため、GIFの256色制限や完全透明制限を受けず、フルカラーとアルファ透過を保持
- すべてのフレームを同じ大きさで画面全体へ上書きし、前フレームを消去する必要がない形式で保存する
- 保存直前に生成したAPNGを再検査し、フレーム数、順序、表示時間、無限ループが設定値と一致しない場合は保存を中止する
- 動きの速さはGIFと同じ100分の1秒単位のフレーム間隔に丸め、丸めが発生した場合は完了メッセージに表示
- APNGのループはGIFと同じ無限ループです。ブラウザがAPNG再生に対応しない場合もPNGファイルとして保存できます

APNGはフレームごとのPNGデータを保持するため、同じサイズと長さのGIFより大きくなることがあります。性能が控えめな端末では256pxまたは360px、短い長さ、8fpsから試してください。

写真アプリのAPNG対応はアプリごとに異なります。写真アプリがAPNGを静止画として扱う場合でも、保存後の「保存したAPNGを別タブで開く」から対応ブラウザで動きを確認できます。写真アプリとの互換性を優先する場合は、アニメーションWebPも試してください。

### アニメーションWebP

- GIFと同じ長辺256px、360px、480px、2秒から5秒、8fps、10fps、12fpsを使用
- 総処理画素数は通常端末で1400万画素以下、端末メモリが2GB以下の場合は800万画素以下
- 推定出力は通常端末で24MB以下、端末メモリが2GB以下の場合は12MB以下
- WebP画質は60パーセントから100パーセントで、初期値は95パーセント
- Canvas標準のWebP出力を使うため、現行実装は非可逆圧縮です。ブラウザ標準APIには可逆WebPを指定する共通手段がないため、可逆と偽って保存しません
- 各フレームのWebP実データを検査し、RIFF、WEBP、VP8X、ANIM、ANMF、ALPH、VP8またはVP8Lの順序とサイズを確認
- フルカラー、Canvas WebPが持つアルファ、フレーム順序、表示時間、無限ループを保持
- 表示時間はGIFのフレーム間隔を10倍してミリ秒へ変換します。ブラウザや再生機器が10ミリ秒程度の短い表示時間を丸める場合があります
- WebPに対応しないブラウザでは選択肢を無効化し、GIFまたはAPNGを案内

アニメーションWebPの実画像デコードは、保存に使ったブラウザのWebPデコーダーが行います。CIではRIFF構造、フレーム構造、サイズ、表示時間、ループ、透過フラグを検査し、実ブラウザでは保存後の再生を手動確認します。

### 静止画像

- 長辺480px、720px、1080px、1440px
- PNG、JPEG、WebP
- JPEGとWebPは画質60パーセントから100パーセント
- 合計400万画素以下

## 性能が控えめな端末での推奨設定

まずは360px、3秒、10fps、色品質は標準から試してください。標準は色味と処理速度のバランスを優先します。より細かく色を分析したい場合だけ高画質を使用してください。動作が重い場合は256px、8fps、色品質を軽量へ下げてください。

低メモリ端末では入力画像の合計画素数に厳しい上限を適用します。出力時は必要に応じて描画用に縮小します。ブラウザが端末メモリ情報を提供しない場合は、保守的な上限を使用します。

## 更新が反映されない場合

画面下部がBuild 20であることを確認します。Build 5以前の場合はページを閉じて開き直し、再読み込みしてください。ホーム画面へ追加した版も、いったん終了してから開き直します。

Build 20では、APNGの各フレームを前フレームの消去に依存しない全画面上書きとして保存し、保存前に完成したAPNGのフレーム数、順序、表示時間、無限ループを再検査します。別タブのプレビューに必要な中央配置用CSSは同一オリジンの外部ファイルから読み込み、Blobページが元ページのセキュリティ設定を引き継ぐタブレットやスマートフォンでも、ブラウザ既定の余白で左上へ寄らず、画面中央に表示します。画像を選ぶとプレビューの再生を開始し、「プレビューを別タブで開く」ではGIFを事前生成せず、現在の動きをCanvasで再生します。別タブ用のBlob URLをそのまま開き、設定はページ内の検査済みdata属性から読み込みます。9種類の動きは画面上のボタン一覧から直接選択できます。設定値は同じブラウザ内に残ります。速度変更用に読み込んだGIF、最後に生成したGIFの再生成用設定、画像そのもの、別タブ表示用の一時URLは保存されないため、ページを開き直した場合はGIFをもう一度選択してください。

## 検査

Node.jsだけで実行できます。追加パッケージは不要です。

```bash
node --check app-core.js
node --check motion-model.js
node --check gif-retimer.js
node --check apng-encoder.js
node --check webp-encoder.js
node --check app.js
node --check app-image.js
node --check app-export.js
node --check app-events.js
node --check gif-encoder.js
node --check gif-worker.js
node --check sw.js
node scripts/test_app_core.mjs
node scripts/test_motion_model.mjs
node --max-old-space-size=64 scripts/test_gif_encoder.mjs
node scripts/test_gif_retimer.mjs
node scripts/test_apng_encoder.mjs
node scripts/test_webp_encoder.mjs
node scripts/test_gif_disposal.mjs
node --max-old-space-size=64 scripts/test_gif_dominant_color.mjs
node scripts/check_static.mjs
```

動きのテストは、「左右に傾く」が足元、「振り子」が上部を支点にすること、「呼吸」が縦横に異なる伸縮になること、「ゆっくり拡大」が等倍から拡大して等倍へ戻ること、「弾む伸縮」が足元寄りを支点に横に広がり、縦に縮むこと、逆向き設定でも周期が壊れないことを数値で確認します。app-coreのテストでは、動きの速さからGIFとAPNGのフレーム間隔、概算再生時間、総処理画素数、推定メモリが一貫して計算されることも確認します。

APNGのテストは、Canvas PNG相当のRGBAフレームをAPNGへ組み立て、PNGシグネチャ、IHDR、acTL、fcTL、IDAT、fdAT、IEND、CRC、フレーム数、フレーム順序、表示時間、無限ループ、寸法、透過画素、色を検査します。各フレームの圧縮データを復号し、入力フレームと一致することも確認します。壊れたCRC、チャンク長、寸法、総展開画素数を拒否することを確認します。

アニメーションWebPのテストは、正しいRIFFチャンク順のCanvas WebP相当のVP8、VP8L、ALPHフレームを組み立て、RIFF長、チャンク名、チャンク長、WEBP、VP8X、ANIM、ANMF、フレーム順序、表示時間、無限ループ、寸法、透過、可逆ビットストリームの保持を検査します。壊れたRIFF長、チャンク長、寸法、表示時間、総展開画素数を拒否することを確認します。追加ライブラリなしでは実ピクセルをデコードせず、保存に使ったブラウザの標準デコーダーで手動確認します。

GIFのテストはヘッダーだけを確認しません。通常サイズの高エントロピーフレームを圧縮後にLZW復号し、全画素の色番号が元フレームと一致することを確認します。これにより、9ビットから12ビットへの切り替えや4096項目の辞書初期化で生じる破損を検出します。

GIF速度変更のテストは、速度変更前後のバイト列を比較し、各フレームの表示時間の2バイト以外が一致することを確認します。フレーム数、透過、無限ループ、画像データを保持し、表示時間のないGIFへ必要な制御情報を追加できることも検査します。

肌色、グラデーション、彩度の異なる色を含む検証画像を減色し、平均色差とRGB各チャンネルの偏りが上限内であることも確認します。透明GIFでは、画像を3位置へ移動させ、前の位置が次フレームへ残らないことを合成結果まで検査します。

白背景が半分以上を占める横長イラストを正方形の透明Canvasへ配置した条件も再現します。255色のパレットが黒数色へ崩れないこと、白が白として残ること、平均色差が上限内であることを64MBヒープで確認します。

GitHub ActionsのChecksでは、Pull Requestとmain更新時に同じ検査を実行します。公開用ワークフローでは、検査が成功してからPagesへ公開します。公開サイトはDeploy GitHub Pagesの成功後と毎週、Live site checkでBuild 20の公開ページ、実行ファイル参照、別タブCanvasプレビュー、GIF、APNG、アニメーションWebPの保存形式表示を確認し、公開中のエンコーダーとGIF速度変更処理の回帰テストを実行します。

## 変更時の基本ルール

- 外部API、CDN、解析タグを追加しない
- eval、new Function、innerHTMLによる文字列挿入を使わない
- 新しい入力形式を増やす前に実ヘッダー検査を追加する
- 出力解像度やフレーム数を増やす前に処理量上限を見直す
- 動きの名前、支点、座標、伸縮を変更した場合はmotion-model.jsと数値テストを同じ変更で更新する
- GIF圧縮を変更した場合は、生成ファイルを実際に復号する回帰テストを追加する
- GIF速度変更を変更した場合は、画像データを変えず表示時間だけが変わるバイト単位の回帰テストを追加する
- GIFの減色処理を変更した場合は、平均色差、RGBの偏り、支配色画像を検査する
- パレット分割では空の色グループを作らない
- 透明GIFを変更した場合は、前フレームの描画が残らないことを検査する
- 実行ファイルを変更した場合は参照URLとBuild番号を進める
- app.js群の画面依存処理とapp-core.jsの検査処理を混ぜない
- 画像を読み込んだときはプレビュー再生を開始し、別タブ用プレビューも静止画へ戻さない
- 別タブ表示用の一時URLは新しい表示を作る前、画像を外したとき、pagehide時に表示用ファイルと中央配置ページの両方を破棄する
- キャッシュ対象を増やす場合はsw.jsの許可一覧へ明示する
- 変更後はMAINTENANCE.mdの手順で確認する
